Missing Data

Types, Detection, and Pandas Imputation

Why Missing Data Matters

  • Biases estimates and relationships if handled poorly
  • Reduces statistical power (less data after dropping)
  • Causes errors in modeling pipelines

Thesis: Your strategy must match why the data is missing.

What Counts as “Missing”?

  • Canonical: NaN, None, NaT
  • Non-standard placeholders: "", "NA", "?", "Unknown", 999, -1
  • Not missing: true zeros; a valid category like "Unknown" (if chosen)
  • Pandas may parse placeholders as strings unless normalized

Always normalize sentinels before analyzing — pandas won’t catch 999 for you.

Types of Missingness

  • Structurally Missing — missing due to data structure
  • MCAR — Missing Completely At Random (no pattern)
  • MAR — Missing At Random (depends on observed variables)
  • MNAR — Missing Not At Random (depends on the unobserved value itself)

Structurally Missing

  • Missing due to the structure of the data
  • Examples: male participants don’t have pregnancy questions; unemployed don’t have employer questions

Best strategies: do nothing, create a “not applicable” value, or analyze separately.

MCAR — Missing Completely At Random

  • Missingness independent of both observed and unobserved data
  • Examples: lab technician spills a sample; survey printing error
  • Heuristic: distributions look similar for rows with/without missing values

Actions: drop a small fraction; mean/median imputation is acceptable. Caveat: dropping still reduces power.

MAR — Missing At Random

  • Missingness relates to observed variables, not the missing value itself
  • Examples: patients with lower BP less likely to have cholesterol measured; older patients more likely missing weight
  • Heuristic: missingness rates differ across observed groups

Prefer conditional strategies: group-wise imputation. Caveat: a global mean may bias results if groups differ.

MNAR — Missing Not At Random

  • Missingness depends on the missing values themselves
  • Examples: people with lower income less likely to report; depressed participants less likely to answer depression questions

Actions: keep a missingness indicator; allow NA to persist; add a “Not reported” category; run sensitivity checks. pandas imputation can’t “fix” MNAR — document assumptions.

MAR vs MNAR

If MAR

  • Multiple imputation works
  • Prediction models make reasonable estimates
  • MLE approaches are valid

If MNAR

  • Imputation may introduce bias
  • Missingness holds hidden info
  • Need sensitivity checks + documentation

MAR or MNAR?

Scenario 1: Younger people are more likely to skip the income question because they don’t know it.

Answer: MAR — missingness depends on observed age.

MAR or MNAR? (cont.)

Scenario 2: People with higher income are more likely to skip the income question because they don’t want to disclose it.

Choosing a Strategy (Mini-Flow)

  1. Assess likely mechanism: MCAR, MAR, or MNAR?
  2. Measure extent: % missing by column and by row
  3. Consider downstream use: summary stats, modeling, visualization

Match the method to the mechanism — there is no universal best choice.

Detecting Standard Missingness (pandas)

  • Quick scans: df.info(), df.isna().sum()
  • Row-level share: df.isna().any(axis=1).mean()
  • Dtype surprises can signal placeholders
df.info()
df.isna().sum().sort_values(ascending=False)

Detecting Non-Standard Missingness

  • Coercion: pd.to_numeric(df["col"], errors="coerce")
  • Frequency spikes: df["name"].value_counts().head(10)
  • Normalize sentinels at read time
sent = ["NA", "N/A", "?", "Unknown", "999", "-999", ""]
df = df.replace(sent, np.nan)
# Or at read:
df = pd.read_csv("data.csv", na_values=sent)

Visualizing Missingness (Quick)

Column bar — share missing per column:

Heatmap — where missingness lives:

sns.heatmap(df.isna(), cbar=False)

Drop vs Impute: Tradeoffs

Drop

  • Simple; removes problematic rows/cols
  • Cost: data loss; bias if not MCAR

Impute

  • Preserves dataset shape
  • Cost: distorts distributions/correlations if assumptions fail

Dropping with Control (pandas)

# Drop rows only if key columns missing
df = df.dropna(subset=["age", "income"])

# Drop columns with too many missings
# (keep if >= 40% present)
thresh = int(0.4 * len(df))
df = df.dropna(axis=1, thresh=thresh)

Always compare df.shape before/after, and document the fraction removed.

Mean Imputation (Numeric)

df["age"] = df["age"].fillna(df["age"].mean())
  • Strengths: simple, fast, preserves size
  • Weaknesses: shrinks variance, distorts tails, biases correlations toward 0
  • When: symmetric distributions, low missingness, MCAR-ish

Median Imputation (Numeric, Robust)

df["income"] = df["income"].fillna(df["income"].median())
  • Strengths: robust to outliers/skew
  • Weaknesses: compresses variance; may flatten multimodality
  • When: skewed data, outliers, MCAR/MAR (global)

Forward / Backward Fill (Ordered / Time Series)

# Globally:
df["price"] = df["price"].ffill().bfill()

# Within groups (safer):
df = df.sort_values(["id", "time"])
df["x"] = df.groupby("id")["x"].ffill()
  • Strengths: good for continuous sensors/sequences
  • Weaknesses: dangerous across entities; must group properly

Missingness Indicator Columns

df["age_missing"] = df["age"].isna().astype("int8")
df["age"] = df["age"].fillna(df["age"].median())
  • Strengths: keeps signal that values were missing (useful for MAR/MNAR)
  • When: MNAR suspected, transparency, later modeling

Pair the indicator with an imputation — the flag preserves that data was missing.

Nearest / Closest Value (Index-Based)

df = df.sort_values("timestamp").set_index("timestamp")
df["y"] = df["y"].interpolate(method="nearest")
  • Strengths: leverages local neighborhood
  • Weaknesses: assumes local similarity; unsafe for unordered/categorical data

Group-Wise (Conditional) Imputation

df["income"] = df["income"].fillna(
    df.groupby("region")["income"].transform("median")
)
  • Strengths: respects systematic differences across groups (MAR)
  • Weaknesses: unstable for small groups

Check group sizes — a handful of rows makes the group median noisy.

Strengths & Weaknesses (Summary)

Method Best For Strengths Weaknesses
Drop MCAR; small fraction Simple Data loss; bias if not MCAR
Mean Symmetric numeric Fast; simple Shrinks variance; distorts tails
Median Skewed / outliers Robust; better center Still compresses variance
FFill/BFill Ordered series Continuity; local realism Must group; may propagate errors
Indicator MNAR suspected Preserves missingness signal Needs interpretation; not a fill alone
Nearest Smooth series Local info Needs order; unsafe for categoricals
Group-wise MAR Respects group structure Small groups unstable

Measuring Impact of Your Choice

before = df.copy()
# ... do your cleaning ...
after = df.copy()
before.shape, after.shape
before.describe(numeric_only=True)
after.describe(numeric_only=True)
  • Watch shifts in mean/median/variance and correlations
  • Visual spot-checks: histograms, scatter plots pre/post
  • Document: what changed, why, and the assumed mechanism

Key Takeaways

  • Match the method to the mechanism — MCAR, MAR, MNAR drive the choice
  • Detect before you act: isna().sum(), sentinel scans, visual checks
  • Dropping is simple but costly — bias if not MCAR, power loss either way
  • Imputation preserves shape but distorts distributions if assumptions fail
  • Document assumptions — especially under MNAR, imputation can’t “fix” bias
