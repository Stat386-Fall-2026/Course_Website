Why Embed in EDA?

  • Hypothesis generation: see clusters, manifolds, trajectories
  • Outlier discovery: visually spot anomalies and mislabeled rows
  • Target alignment: color by a variable of interest
  • Batch effects: detect site/collector effects
  • Communication: fast sanity checks and storytelling

EDA with Embeddings: A Practical Workflow

  1. Assemble features and audit missingness
  2. Preprocess: impute / encode / scale
  3. Start with PCA (EVR, scree, biplot)
  4. Try t-SNE / UMAP / PHATE for nonlinear structure
  5. Color by target, batches, time, features, missingness
  6. Overlay outliers, stability checks
  7. Capture hypotheses; plan confirmatory analyses

This is the spine of the rest of this deck — each step gets a closer look.

Missing Data: Quick Principles

Embeddings cannot handle NaNs — you must drop or impute before fitting.

  • Create missingness indicators before imputation
  • Keep indicators for color-by to inspect patterns
  • Choose imputation to match context: median / most-frequent, KNN, model-based

MCAR, MAR, MNAR

MCAR

  • Missingness unrelated to any data
  • Drops a small fraction safely

MAR

  • Depends only on observed variables
  • Group-wise imputation helps

MNAR

  • Depends on the unobserved value itself
  • Needs domain insight & sensitivity analyses

EDA tip

  • If a simple model predicts missingness from observed features better than chance → likely not MCAR

Visualizing Missingness in Embeddings

  • Add *_is_missing indicators to metadata
  • Color by missingness to see clustering
  • MCAR should not cluster
  • Compare against batch / site / time

Report: how missingness was handled — imputation method, indicators kept, assumed mechanism.

Preprocessing Choices Matter

  • Scaling: standardize numerics; robust scaling for heavy tails
  • Encoding: one-hot for categoricals; avoid target leakage
  • Distance metric: Euclidean default; cosine for sparse / high-D
  • Subsampling: embed a subset for large N
  • Random seeds: fix for demos

Different preprocessing → different embeddings. Lock your pipeline and record choices.

Preprocessing Checklist

Imputation

  • Missingness indicators saved?
  • Numeric imputation set?
  • Categorical imputation set?

Encoding

  • One-hot encoding on?
  • Target leakage avoided?

Scaling

  • Scaling after imputation?
  • Robust scale for heavy tails?

PCA: Linear Baseline

  • Finds orthogonal directions with maximal variance
  • Fast, deterministic; axes are interpretable linear combos
  • Use EVR & scree plot to gauge dimensionality

PCA is always the first stop — it gives a sanity check and a reproducible reference point.

PCA — Visualization

PCA visualization — 2D scatter of the first two principal components.

  • Inspect spread, clusters, and outliers
  • Check the scree plot to decide how many PCs to keep

t-SNE: Local Neighborhoods

  • Preserves neighbor probabilities; emphasizes local structure
  • Key knob: perplexity (neighborhood size)
  • Often faster/more stable than t-SNE at larger scales

Inter-cluster distances / areas are not globally meaningful. Use init="pca" and fixed seeds.

t-SNE — Visualization

t-SNE visualization — 2D scatter emphasizing local neighborhoods.

  • Tune perplexity and re-run to check stability
  • Compare clusters to PCA for contrast

UMAP: Topology-Aware

  • Builds a fuzzy topological graph; optimizes low-D cross-entropy
  • n_neighbors: local vs global tradeoff
  • min_dist: cluster tightness

Often faster and more stable than t-SNE at larger scales — a good default nonlinear method.

UMAP — Visualization

UMAP visualization — 2D scatter balancing local and global structure.

  • Try a few n_neighbors / min_dist settings
  • Verify clusters persist across seeds

PHATE: Trajectories & Denoising

  • Emphasizes continuous progressions; great for time-course data
  • Manifold-denoising via diffusion geometry
  • Use when you expect arcs / branches rather than compact blobs

PHATE — Visualization

PHATE visualization — 2D scatter revealing trajectories and branches.

  • Ideal for developmental, single-cell, or time-series data
  • Compare arcs against PCA to confirm nonlinear structure

Cheat-Sheet: Which Method When?

PCA

  • Linear global structure
  • EVR / speed / determinism
  • Good first look

t-SNE

  • Local clusters
  • Perplexity sensitive
  • Distances between clusters ≠ meaning

UMAP

  • Local + some global
  • n_neighbors / min_dist control
  • Scales well

PHATE

  • Trajectories / branches
  • Denoising effect
  • Great for progressions

Coloring Strategies

What to overlay on your embedding: - Target / label, probabilities, residuals - Batch / site, collector, time, cohort - Engineered features: score, complexity, text length - Missingness indicators

Use shapes / sizes for a second variable — sparingly, to avoid clutter.

Outliers & QC

  • Inspect whether outliers align with missingness, batches, or data-entry errors
  • Verify suspicious points directly in the raw table before acting

Don’t delete on a hunch — confirm the row, then document the action.

Common Pitfalls

  • Reading global distances / areas on t-SNE as meaningful
  • Over-interpreting pretty pictures as causal stories
  • Ignoring preprocessing / batch effects
  • Not reporting params / seeds — irreproducible EDA

Key Takeaways

  • Start with PCA — fast, deterministic, interpretable baseline
  • Add nonlinear methods (t-SNE / UMAP / PHATE) for structure PCA misses
  • Handle missingness first — indicators + imputation, then report it
  • Color deliberately — target, batch, time, missingness tell the story
  • Report params & seeds — reproducible EDA beats pretty guesses
